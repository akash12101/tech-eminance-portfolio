Our Delivery Process

What every project goes through before it reaches you.

Most web development companies say they have a process. This page documents ours. The QA checklist, the communication standards, the escalation path and the handover procedure — written down, not just claimed.

Start Your Project → See the Checklist

Why We Document This

Hiring a freelance developer or a web development agency is a bet. You are betting the work will arrive on time, to the right standard, ready to launch or hand to a client you care about. Most agencies and freelancers ask for that trust without showing what they actually do to earn it.

We think that is the wrong approach. A checklist you can read is worth more than a quality guarantee you cannot verify. This page exists because every process described here is something we actually run on every website, ecommerce store, and web application we build — not something we made sound organized after the fact.

If you are evaluating web development partners, use this page to ask better questions of every developer or agency you talk to. And if you choose to work with Tech Eminence, you will know exactly what is happening on your project between the first brief and final delivery.

Delivery Standards

What every project goes through.
No exceptions.

Every project passes through four phases before delivery. Each phase has a defined checklist. Nothing moves to the next phase until the current one is signed off internally.

1 Technical Review
Before development begins
✓
Brief reviewed and scoped
Scope gaps flagged before any work starts.
✓
Tech stack confirmed
Platform, framework, and version requirements agreed.
✓
Design assets checked
Fonts, colours, image resolutions, and file formats verified.
✓
Third-party integrations listed
APIs, payment gateways, CRMs, and any external dependencies identified.
✓
Timeline confirmed with milestones
Review dates agreed before development begins.
2 Development QA
During and post-build
✓
Code review by a senior developer
No code ships without a second set of eyes on the team.
✓
Staging environment tested
All functionality verified on staging before client review.
✓
Forms and checkout flows tested
Every interactive element tested end-to-end.
✓
Console errors cleared
Zero JS errors and resource-loading issues in console.
✓
Content accuracy checked
Text, images, and data verified against the approved brief.
✓
Third-party integrations tested live
Payment, API, and CRM connections verified with real test data.
3 Browser, Device & Accessibility Testing
Cross-environment checks
✓
Chrome, Firefox, Safari, Edge
Current versions on Mac and Windows.
✓
Mobile iOS Safari and Android Chrome
Tested on real devices, not just emulators.
✓
Responsive layout at all breakpoints
320px, 768px, 1024px, 1440px minimum.
✓
Keyboard navigation
Full site navigable without a mouse.
✓
Colour contrast ratios
WCAG AA minimum across all text and UI elements.
✓
Alt text and ARIA labels
Images, icons, and interactive elements correctly annotated.
4 Performance Review
Before handover
✓
Google PageSpeed scored
Mobile and desktop scores reviewed and issues addressed.
✓
Images optimised
Correct format, compression, and lazy-loading applied.
✓
Core Web Vitals reviewed
LCP, CLS, and INP flagged and resolved where possible.
✓
Unused code removed
Dead CSS, unused scripts, and redundant plugins cleared.
✓
Client delivery checklist signed off
Internal QA-completed handover is signed off.
Communication Standards

How we keep you informed
throughout every project.

You should never have to chase us for an update. These are the communication standards every project lead on our team follows.

Dedicated Project Manager

One point of contact per project. Your PM knows your account, attends every briefing, and never passes you along to someone without context.

Your Tools, Not Ours

Slack, Teams, Jira, Basecamp, ClickUp, Notion, or email — we work in whatever project management system you already use. No forcing you into our workflow.

Response Within 24 Hours

All project queries receive a response within one business day. For active builds, most messages are answered the same day.

Milestone Updates

You receive a written update at every agreed milestone — a proper summary of what's done, what's next, and whether the timeline still holds.

Your Brand on Everything

All documents, reports, and communications shared with you are free of Tech Eminence branding unless you ask us to include it — for agency partners, nothing exposes our involvement to your client.

Escalation Path

If something isn't right, there's a clear path to resolve it. You are never left raising tickets and hoping — see exactly how below.

Escalation Process

When something needs to be fixed.
How we handle it.

Problems on projects happen. The clients who stay with us longest are not the ones who never had a difficult project — they're the ones who saw how we handled it.

1

Raise it with your project manager

Your first point of contact for any issue is your dedicated PM. Most issues are resolved at this level within one business day. Your PM owns the resolution, not just the acknowledgement.

2

Escalate to the senior project lead

If the issue isn't resolved, or you're not satisfied with the response, it escalates to the senior lead who has the authority to reprioritise resources and commit to revised timelines.

3

Direct line to the founder

For anything that needs to be decided above the project level, you have direct access to the founder. Long-term client relationships aren't managed at arm's length — if something is genuinely wrong, you speak to the person who built the company.

Project Handover

What you receive.
And what happens after.

Handover is not just sending over a zip file. This is what every completed project includes, and what the post-delivery support window covers.

What is included in every handover

  • Full source code or theme files, clean and commented
  • All credentials including hosting, CMS, and admin accounts, API keys
  • Staging and production URLs with access confirmed
  • Documentation covering key features and configuration
  • Plugin or dependency version list for WordPress and WooCommerce builds
  • Any third-party accounts created during the build
  • Internal QA sign-off sheet showing every check completed

Post-delivery support window

  • Bug fixes related to the delivered scope, at no extra charge, within 30 days
  • Clarification calls on any aspect of the delivered work
  • Guidance on how to present technical decisions to your client or stakeholders
  • Scope extensions quoted separately and scoped in writing
  • Ongoing maintenance available as a monthly retainer if required
